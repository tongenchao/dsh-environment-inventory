# 安全规则（用户全局指令，所有会话自动生效）

以下规则适用于本机所有会话。用户明确表示最担心「误删文件」，因此删除类操作必须最保守。

## 一、删除/覆盖铁律（最高优先级）

1. **任何删除、覆盖、移动、清空操作**（包括临时文件、缓存、构建产物）之前，必须先向用户列出**完整路径清单 + 原因 + 影响范围**，得到用户明确同意后才执行。工作区内部的文件也一样要先报告。
2. 删除用户文件时**禁止直接永久删除**（Remove-Item / del / rm / fs.unlink），一律使用保险脚本：
   `C:\Users\32169\Desktop\harness测试\safe-delete.ps1 -Path <路径> -Reason <原因>`
   它会把文件**移入 `_trash` 回收目录**（带时间戳）并写入操作日志，用户随时可恢复。
3. `C:\Users\32169\Desktop\harness测试\_trash\` 是用户恢复误删的最后机会：**绝不清理、绝不删除**里面的内容，除非用户明确要求。
4. 用户桌面、文档、图片、下载、项目源码等目录下与当前任务无关的文件：**一律不碰**。只读可以，改删不行。
5. 清理系统临时目录（%TEMP%、node_modules/.cache 等）时，只删除**本次任务自己创建**的文件，且仍须先报告。

## 二、权限边界

6. 默认保持 `workspace-write`（只能改工作区文件）。需要 `danger-full-access` 时必须：说明用途、列出要动哪些文件、说明如何恢复，并等待用户批准。未获批准自动失败。
7. 不修改用户未要求的系统设置、防火墙规则、注册表、已安装软件；安装/卸载软件必须先征得同意。
8. 不向公网暴露本机服务；不建立 ngrok/公网隧道（本机 harness 可执行任意代码）。

## 三、审计与透明度

9. 每次删除/移动操作都写入 `C:\Users\32169\Desktop\harness测试\操作日志.log`（safe-delete.ps1 自动记录）。
10. 操作日志与 `_trash` 目录对用户完全透明，用户可以随时查看；发现异常立即停止并向用户说明。

## 四、外网代理自助闭环（用户授权，任务中自动执行）

本机有两个梯子，端口不同，**通常不同时开**（用户配置，勿改动）：

- **好好云**（hhycenterCore）→ `127.0.0.1:7890`：git 全局代理与系统代理的默认端口
- **Clash Verge**（verge-mihomo）→ `127.0.0.1:7897`：混合端口

任务需要外网时，**无需询问用户，自主执行以下闭环**：

1. **探测可用代理**：`curl -s -o NUL -w '%{http_code}' http://127.0.0.1:7890/` 与 7897 同理（200/400/407 = 活着）。都活着优先 7890（与 git/系统代理默认一致）；7890 挂则用 7897。
2. **命令显式走代理**（不依赖系统代理）：
   - curl：`-x http://127.0.0.1:<port>`；PowerShell：`-Proxy 'http://127.0.0.1:<port>'`
   - git：默认全局 7890 即可用；若走 7897 用配方
     `git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 -c http.sslBackend=openssl`
   - TLS 报 `SEC_E_NO_CREDENTIALS`/schannel 错误时，切 OpenSSL 后端：git 加 `-c http.sslBackend=openssl` 或设 `GIT_SSL_BACKEND=openssl`
   - playwright/浏览器：`chromium.launch({ proxy: { server: 'http://127.0.0.1:<port>' } })`
3. **需要开系统代理时**（浏览器类任务）：改注册表 `HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 前**记录原值（Enabled/Server）**，用完**恢复原状**（Enabled 和 Server 都要还原），并写入操作日志。
4. **用完自动关闭**：任务外网需求结束后恢复系统代理原值；**不杀梯子进程、不改 git 全局配置**。
5. 状态查看工具（只读，不改任何配置）：`C:\Users\32169\Desktop\harness测试\proxy.ps1 status | check <port>`

## 五、重启策略（用户授权）

用户明确要求：不需要手动重启按钮；以后但凡需要重启，自动重启并自动激活继续。

1. **优先动态机制**：插件/配置类变更一律走免重启方案（dev_* 注入、热重载、patch 修复、路由清理、junction 自愈），不触发重启。
2. **兜底自动重启**：仅当变更超出动态机制范围（DSH 核心/壳层修改、版本升级、profile 结构级变更）或服务崩溃/异常时，才需要重启——此时**自动执行重启并自动激活继续**（重启后自动恢复当前会话继续任务），无需询问用户。
